# 快照诚实与失败方向

本文是本库的 **软监督原则**（缩写版），不是字段级 API 合同。字段与错误码以 `docs/AI与人类/需求拟定/04-公开API与快照DTO.md` 为准。

## 1. 核心抽象

**快照须可解释：**

> 每一份 `TSenseSnapshot` 在交给调用方之前，必须能说明：当前 `root` 仍有效、`pageTitle` 是现读而非缓存、自主菜单里的 id 都来自点位或岛展开、generic `ref` 没有混进 `playables`；模式与附件不得假装「还能点」。

这里的「证」可以是：

- `pageTitle` 来自本次扫描的隐藏节点（空或缺失 → `null` / `degenerate`）；
- `view: "blocking-layer"` 时，`playables` 只含该层子树；
- `code: "BLOCKED_NO_PLAYABLE"` 时 `playables` 为空且 `fallback` 非空（或拍失败时 `screenshot: null` 但 a11y 仍在）；
- 明确的 `mode` / `code`，而不是把挡层底下的按钮留在列表里让 Agent 去点。

## 2. 何时启用

出现下列情形时应主动对照本文：

- 修改 pagetitle 分流、焦点层收口、stacking 收入；
- 修改 island 展开、id 是否与树同一套；
- 修改 generic fallback / 截图附件；
- 讨论是否把 a11y `ref` 交给 bot、是否推送全量快照、是否引入 Playwright 当运行时依赖。

## 3. 基本判断（每份快照至少心里答）

1. **看的是哪一页：** `pageTitle` 现读结果是什么？  
2. **现在是哪种模式：** autonomous 全页 / 焦点层 / 退化？  
3. **凭什么收口或附 generic：** `cover=most`？层内 playable 数？  
4. **失败一半会怎样：** 截图失败是否仍给 a11y？是否把空菜单说成可点？  
5. **如何回报：** `mode` / `view` / `code` / `fallback` 是否诚实？  

## 4. 硬性失败方向（与 codingRole 一致）

| 场景 | 方向 |
|------|------|
| 无 pagetitle | `mode: "degenerate"`，不要伪造自主菜单 |
| 大挡层且层内 0 playable | `BLOCKED_NO_PLAYABLE` + `fallback`；`playables: []` |
| 岛 slot 找不到 | 不把该合成 id 写入 `playables`（展开失败不是静默丢项假装没有岛） |
| 截图失败 | `screenshot: null`，a11y 仍给；不得整份 snapshot 假成功成「看不见也算看见」 |
| generic 节点 | **禁止**合并进 `playables[]` |

**禁止假菜单：** 把不可点、未打点、或已被焦点层收掉的目标写成可操作 id。

## 5. 与控制 / 编排的边界

- 本库不负责点下去——那是 in-page-bot。`resolve(id)` 只把菜单 id 映射到瞄准节点，不 `click` / 不派发。
- `resolve` 必须与该帧 `playables` 同一套收口：层外、空挡层、generic `ref` 不得解析成真可点 Element。  
- 本库不负责握手、`pageId`、BOM `escapes`——那是 in-page-playable。  
- 本库负责证明：「按感知合同扫了这一帧，并诚实分类」。

## 6. STOP

合同内缺口关闭、核心 DTO 契约有测试后，停止用原则文扩张范围；进入 playground 对照真实 DOM。
