# 01 — 产品概述与边界

## 1.1 产品是什么

**in-page-sense** 是一个浏览器端 npm 组件：在目标页面（或 iframe）的 `root` 内扫描业务点位与挡层，产出一份 **短菜单 + 浅结构** 快照，供 Agent / 编排库决定「能看见什么」。

它解决的问题：

- 在 **已打开的页面会话** 里可编程地「看」DOM（调试、联调、Agent 通道的感知端）。
- 提供可复用、与业务解耦的 **感知器**，而不是绑定某一站点的选择器脚本。

## 1.2 为谁服务

| 角色 | 用法 |
|------|------|
| 库维护者 | 实现扫描 / 树 / 退化快照，用 playground 对照 DOM |
| 宿主应用（如 SlimVID development） | 打点并注入后调用 `createSense().snapshot()`；闸门由宿主负责 |
| 编排库（in-page-playable） | 把快照装进带 `pageId` 的信封；用 `resolve(id)` 得到 Element 再交给 bot；按 `code` 决定是否开放 BOM |
| 控制库（in-page-bot） | **不**调用本库；只接收 Element / 坐标 |

## 1.3 「原子化」定义

**职责原子，不是 API 原子。**

| 是 | 否 |
|----|----|
| 本包只负责感知与快照 DTO | 本包负责 `click`、reload、插件握手 |
| `snapshot()` 内部可以扫点 + 编树 + 必要时拍附件 | 必须把每个 querySelector 都暴露成唯一对外 API |

## 1.4 信任与作用域（诚实合同）

| 档 | 做法 | 本库 V1 |
|----|------|---------|
| 页内扫描 | 读当前 `root` 的 DOM / 计算样式 | **唯一实现** |
| 浏览器自动化感知 | Playwright `ariaSnapshot`、CDP DOM | 不做运行时依赖 |
| 系统截图 / OS 窗体 | 占机、权限 | 不做 |

设计取舍（已对齐）：

- 自主页靠宿主打的 `data-e2e-*`，不靠通用 a11y 考古当主通道。
- 无点位页才走配额内退化快照。
- 截图是校对附件，不是点击坐标真源。

## 1.5 版本边界（V1）

**做：**

- `createSense` + `snapshot()` → `TSenseSnapshot`
- `resolve(id)` → 菜单 id 对应的瞄准 Element（与 snapshot 同一套收口）
- 自主：playables / contents / asciiTree / stacking / 焦点层
- 空挡层：同一次拉取附 generic
- 退化：无 pagetitle 时的普通快照
- TypeScript、ESM、类型导出、playground、契约测试

**不做：** 见 [06-范围外与集成示意](./06-范围外与集成示意.md)。
